# 权重工作流 0.2.20

本版复用原六类预算与优化器，新增以下流程配置。详细流程及新手入口使用相同检查和写入路径。

## MMD 表驱动识别

在“输入与扫描”选择 VRC、MMD 通用或 MMD · R4 Liv，可指定模型补充 JSON。通用表为仓库 `bone_profiles/mmd_conventions_v1.json`，模型证据为 `mmd_r4_liv_v1.json`。这两份原表仍是维护源，不另外复制硬编码 MMD 身体骨名单。

识别统一处理 NFKC、日文元数据与 `.L/.R` 别名；别名碰撞、实名与日文名冲突进入待审核。研究表中的 PHYSICS_CANDIDATE 不自动成为 DYNAMIC，未知骨和身体扩展仍需按当前资产确认；模型历史父链只作为证据，不覆盖当前骨架。映射字段仍分为权重目标、动作目标和源参考骨。手指保持对应指别且默认关闭，指节映射需核对，不按编号硬套。

源动作采样可选普通 FK/LBS，或“保留源约束求值”。后者使用显式采样契约，保留必要 MMD 约束，严格核对实际 Blender 求值，不删除辅助骨贡献以通过检查。目标骨架仍要求已完成动骨接入；本版不自动推断衣物骨归属或运行时物理设置。

## 两种冻结源参考

- 适配前源参考：原衣物、原权重、源骨架；与目标保持可靠的顶点拓扑对应。
- 当前适配网格参考：源输入已经是适配网格，但仍保存完整未传递原权重和源骨架。与目标静止世界坐标必须一致（1e-5 容差）。这不是从已传递权重反推原预算。

准备初值时先保存完整 `before.blend`，再冻结源网格和独立源骨架，保存 source-snapshot / reference 配置。源参考的几何、权重、骨架和约束被修改时拒绝复用。两种模式都不解决任意异拓扑对应，也不能仅凭顶点数相同认定索引语义对应。

## 通用优化后碰撞复核

默认“保存副本并选点复核”：优化成功且预算、固定动骨/手指、绑定、源参考、动作验证等非碰撞检查通过后，可以保存独立优化副本。碰撞不会单独阻止保存，原严格 `accepted` 报告不改写。

结果有碰撞时标记 PENDING，选中相关顶点，报告每个姿态既有及新增相交三角形对、穿入样本变化、最大深度变化。顶点选区包括三角形相交、顶点及面内穿入样本和共面歧义涉及的顶点。由于选区是多个动作的并集，静止姿态未必能看到所有问题。

“选择碰撞顶点”可重新显示选区，“回退上一版本”恢复上一副本显示，保留本次结果隐藏。每次优化写入自动保存当前阶段 `result.blend`，不覆盖用户源文件。仅动作优化的新手预设默认关闭硬碰撞迭代；仍执行完整碰撞诊断。可选“严格无碰撞”恢复原写入门槛，也可以主动开启硬碰撞迭代，但求解不可行不能冒充有效结果保存。新手连续流程遇到 PENDING 会停在该结果，不自动进入末端精调。

排除 bnip 是目标权重通用选项：初值将其份额补至同侧实际加权 bust，优化同步排除，保持躯干和动骨预算。

## 打包与验证

使用 `python tools/build_addon.py <输出.zip>`，会将仓库权威 JSON 打包到安装目录 `kk_vrc_cloth_tools/bone_profiles/`；源码运行优先读取仓库表，安装版读取随包数据。

回归包括已有 VRC 两阶段流程、新手路径、MMD 名称冲突/手指识别、当前适配参考冻结、真实 OSQP 求解、碰撞副本保存选点回退、冻结参考篡改拒绝。没有替用户重新计算当前 Liv 裙子的已验收权重。

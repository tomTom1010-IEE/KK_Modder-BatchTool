# 带动骨衣物权重迁移

先保存原衣物的变形设计，再用目标素体提供新的身体骨分布。按观察到的权重特征选择策略，不按“裙摆”“袖带”等部件名称决定。数值守恒不等于动作验收通过。

## 输入与范围

- 确认原衣物、迁移后衣物、目标身体和目标骨架。先完成所需的几何适配与骨架接入；需处理这些内容时参阅同级 `blender-transfer-garments`、`blender-fit-loose-garments`。
- 用完整原权重快照，核对顶点索引及拓扑；不能从已经传递、归一化或擦除后的权重反推原份额。拓扑不同时先建立可靠对应，不能仅按顶点数相同认定对应。
- 用户已有可恢复备份时无需重复要求确认。仍保存权重快照、对象身份和本轮配置；快照只恢复权重，不能替代整个模型备份。
- 本任务不默认改变几何、法线、UV、材质、骨架结构、形态键或物理参数。恢复权重不能用整个旧 blend 覆盖用户后续的其他修改。

## 骨骼角色与特征

明确分类：`BODY`、保留衣物影响的 `DYNAMIC`、明确弃用的 `DROP`、非变形组 `IGNORE`。辅助骨、乳房骨、扭转骨和控制骨必须检查真实用途、父链及绑定；非 Humanoid 不自动等于动骨，不写死 VRC/MMD 命名。

源与目标的准入规则不同：源端必须保留完整有效变形贡献，目标端身体权重只允许写给目标素体实际存在正权重的骨骼，已确认保留的衣物动骨另行处理。不能只看 use_deform 或骨名。读取插件 `vrc_bone_rules.VRC_WEIGHT_POLICIES` 与实际父链、绑定核对；非该配置的模型由 Agent 明确角色，不能套用 VRC 名称。嫁接时不复制原身体辅助骨，不代表源动作参考可以删掉它的权重。

使用插件分析原权重：
- `ZERO_BODY`：身体份额为零，禁止采样引入身体权重。
- `BODY_ONLY`：身体份额为一，区域内部可使用可信目标采样。
- `STABLE_MIXED`：邻域身体份额及内部语义分布稳定，优先语义映射；不能据此断言刚体。
- `VARYING_MIXED`：保留逐顶点混合份额，再决定内部采样或映射。
- `UNWEIGHTED`：报告并保留，不把失败当作零预算。

当前稳定判据是一环邻接及容差，只是证据。断缝、独立层、局部变化和不同原始总量会影响判断。

### 调用脚本前的模式适用范围

Agent 须先判断动骨影响区域中的身体权重是否属于当前覆盖的两种模式：
- **均匀模式**：区域中保留稳定的身体跟随影响。
- **边缘渐变模式**：身体影响从连接边缘向动骨自由区域连续过渡、衰减。

此判断由 Agent 检查原有效权重与拓扑关系完成，不要求向用户逐项报告判断依据。
`STABLE_MIXED`、`VARYING_MIXED` 是数值标签，不能代替模式适用性判断；变化混合不自动等于边缘渐变。
纯动骨的零身体影响仍按零预算处理。

**遇到两种模式的叠加、其他新模式或无法确认适用性的区域，必须告知用户：该区域不在当前算法覆盖范围，不能直接调用现有自动迁移脚本，需要回退到 Agent 手动逐顶点分析，或需要人工处理。**
报告处理限制与下一步即可，不以长篇判断依据替代这一提示。该区域保持原权重，不得先执行脚本再用数值守恒宣称处理成功。
允许只读分析、快照和诊断；已确认符合范围的区域可独立继续。Agent 逐顶点分析后若能制定可靠方案，再按用户授权范围处理；不能仅把置信度改为 0 就当作未覆盖模式已获支持。

## 显式区域配置与 UI

插件 0.2 的权重面板为“输入与骨骼检查 → 区域模式 → 六类迁移与主体优化 → T pose 末端精调”。旧的动骨区域擦除入口不再作为流程步骤。

- `roles` 标明哪些原骨是 DYNAMIC；影响范围从这些骨在原衣物中的实际非零权重取得，不由骨骼头尾位置、空间包围盒或部件名称推断。
- 区域可用动骨链生成，或用对应网格的显式顶点选区覆盖；同一骨链可拆成多个区域。记录拓扑摘要，过期选区需重新捕获。
- 每个区域指定 `UNIFORM` 或 `EDGE_GRADIENT`。前者使初值使用语义映射，后者允许按可信度使用原生采样；不改变原六类预算。显式渐变配置不会被一环 `STABLE_MIXED` 标签覆盖。
- 未确认、复杂混合、混合顶点未被覆盖、不同模式区域重叠冲突：停止对应自动流程并提示 Agent/人工分析。现有 UI 会阻止整轮执行；高级 API 若要只处理已确认子集，须显式限定 indices，并保护未处理顶点。
- `reviewed_patterns` 只是优化导出的适用范围声明，不是“每区域模式”配置。实际初值策略通过 `region_modes` 逐顶点传入。模式不是材质刚性标签，也不是一组惯性、阻尼参数。

## 六类预算与手指

六类为躯干（含头颈）、左臂、右臂、左腿、右腿、保留动骨。源、目标的身体组分别提供显式区域表；肩骨等边界骨需明确归属。

每个顶点每个类别的新总量 = 原类别总量 /（原有效身体总量 + 原保留动骨总量）。非变形组不计入预算；实际参与变形的身体辅助骨必须计入，不能按辅助骨名称删除后归一化。原类别为零时新类别必须为零；不能只检查全网格或整体身体总量。

类别内部才允许换成目标分布：可信原生采样、语义映射或两者混合，各候选先归一化，再乘预算。动骨保持原相对贡献。类别候选不足时用映射，不放大极小的偶然采样；默认 0.05 是可调筛选阈值，不是删除原影响的阈值。

提供完整 `finger_policy`：标记源与目标手指，默认不启用任何指别；用户或原设计明确需要时指定允许指别，并确认指节映射。手掌、手腕不能当成手指一起删除。
- 所有采样手指影响都过滤。
- 启用的原手指份额预留，再语义映射回填；不能先分配满额预算后追加。
- 未启用的原手指份额按明确映射并入同侧非手指预算，不能丢弃后全局归一化而改变动骨比例。
- 完全省略手指策略是兼容旧接口的行为，并不表示已经排除手指。

## 调用和执行

读取 [插件调用参考](references/plugin-api.md)。实际求解和写入调用插件，不在临时脚本中重新实现守恒算法。

1. 确认加载的插件路径及接口版本；仓库源码、已安装目录和旧 UI 可能不同。
2. 读取场景模式、修改器、姿态、约束、共享网格和锁定组。身体采样姿态与衣物计算空间须一致；不可在屈肘身体上采样静止衣服。
3. 建立快照、角色、区域、骨骼映射和手指策略；运行特征分析，并通过上述模式适用性判断。未覆盖区域从自动迁移范围排除并告知用户。
4. 空间传递使用 Blender 自带 Data Transfer 的 `POLYINTERP_NEAREST`。不得悄悄换成旧手工传递、Robust 或其他求解器。先在临时副本采样，避免改动目标和原快照。
5. Agent 对不可信区域判断并调整候选/置信度；只针对有证据的问题骨作清理，不能普遍清除胸部骨或手指之外的辅助变形骨。
6. 通过 `prepare_plan` 或 `prepare_from_body` 生成六类计划，检查回退列表、零类别、新手指和缺失映射，再用 `apply_plan` 写入。
7. 检查实际写入的类别份额、动骨及指定手指份额、无效绑定、受保护对象；以抬臂、屈肘、躯干、独立动骨和启用手指动作检查拉扯。姿态检查后恢复全部临时状态。
8. 报告数值结果与视觉限制，说明是否保存 blend、是否更新安装目录/UI。按用户要求保存结果，未保存不可声称已落盘。

不要在新结果后运行旧的“动骨区域擦除身体权重”或全组归一化，否则会破坏预算。重复运行始终基于同一个原快照重新规划，不在上轮结果上累积。

## 两阶段运动响应优化

需要复现换素体后的运动特性、修正主体或腕部响应时，读取 [优化与 UI 调用参考](references/optimization-workflow.md)。仍调用插件求解，不在临时脚本中另写优化器。

1. 用完整原源权重计算六类与手指预算；初值来自语义映射、可信的原生最近面插值或用户已审核的对应顶点分布，不用随机权重初始化。
2. 以原衣物和已雕刻适配衣物的成对静止坐标、局部解剖参考框架构造动作参考，不能直接回归两个不同身材模型的世界坐标绝对距离。support 的参考框架可取所属上下臂，但动作采样仍使用每根 support 自己的实际矩阵。
3. 源数值 LBS 必须与 Blender 逐姿态求值的 `actual_source` 相符，目标基线也须通过 LBS 对照。缺失源有效辅助骨、坐标不一致或不支持的驱动/约束必须中止，不能仅凭拟合误差下降验收。
4. 第一阶段在常用宏观姿态及较低权重的固定种子随机姿态下，用 OSQP 优化身体类别内部分布。六类预算非负守恒，原动骨和已启用手指贡献冻结；纯动骨几何不作为身体权重优化目标。
5. 第二阶段以第一阶段结果为初值，身体保持 T pose，仅采样明确配置的末端动作骨。限定顶点核心、拓扑过渡环、同侧允许身体骨和修正幅度；选区外权重及采样位置不变。不能默认所有手部辅助骨都允许加入权重。
6. 每阶段使用独立验证姿态，检查响应误差、范围内顶点与面穿模、预算、固定份额、白名单和过期状态。独立验收失败不可写入；`solver=solved` 不等于验收通过，也不能手改 accepted。
7. 通过后写入独立副本，保存配置、导出、候选、验证与写入报告。区分数值验收和用户视觉验收，并说明未检查的连续时间、衣物自碰撞及其他叠穿碰撞。

源角色修正后，应从完整原权重重新生成预算；不能沿用错误删骨归一化后的动骨/手指份额。每轮记录实际加载路径、是否同步安装目录、是否保存 blend，避免用旧 UI/旧模块缓存运行新计划。

## 语义复杂时回退给 Agent 判断

插件分类不等于最终语义。领口贴近袖子、腋下、多层相邻布面、错误父链、稳定标签与实际模式不一致时：

- 查看原模型该区每顶点的有效权重、邻接连续性、骨骼父链及变形；空间相近不是同一裁片或同一类别的证据。
- 在已覆盖模式内，原语义与目标映射明确但空间采样不可信：对显式顶点范围设置采样置信度为 0，使用映射。不要修改六类预算去掩盖候选错误。此回退不能用于跳过未覆盖模式的提示与逐顶点分析。
- 身体内部候选可调整，但调整后重新调用插件生成计划；不能直接改带摘要的计划或绕过验证。需试刷时采用可恢复候选，并用同一预算检查。
- 角色或目标映射确实无法判断：保留该区不写入，告知用户需要 Agent 逐顶点分析或人工处理；确有缺失信息时提出具体问题，继续处理已确定区域。不能把未知骨默认为 DROP/DYNAMIC。
- 手工改变原预算或设计分界属于不同操作，需符合用户要求，不以“手动判断”暗中破坏守恒。

## 预留能力：稳定跟随与渐变连接同时存在

遇到同一类别内既有均匀的某骨跟随，又叠加其他骨的渐变连接（如裙子下腰固定跟随加上腰渐变），**主动提醒用户：当前六类算法不能自动分离和保护这两个分量，应实现预留扩展**。

`protected_components=None` 已在插件预留。传入任何非 None 值会明确报未实现，不会忽略后继续执行。尚无承诺的数据格式，不能自行编造配置并称支持。

该情况属于未覆盖的混合模式，不能直接调用现有自动迁移脚本，也不能自动以完整语义映射充当已支持的解决方案。告知用户需要 Agent 手动逐顶点分析、人工处理或实现扩展；分析完成前保留该区原权重。不能自动启用补全或平滑。将来实现需从归一化有效权重识别各骨的稳定/渐变分量，预留稳定分量，只对剩余预算采样，最终恢复六类及动骨预算。该提醒在实际出现此特征时触发，不是定时提醒，也不自动授权实现。
